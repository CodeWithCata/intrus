# Avatars

Read when you touch avatar drawing, the avatar builder or saved player looks. Paths from repo root.

- **`Avatar.svelte`** draws `<Avatar player size />` (`player` = `{ a, l?, ph? }` or a number). Precedence: photo `ph` > builder code `l` (when valid) > legacy index `a`. Always pass the whole player object so `l` is honoured. `AvatarStack` (`players count size`) is the overlapping `.avs` row.
- **There are 48 distinct faces** (`AVATAR_COUNT = BASE_AVATARS (12) × VARIANTS.length (4)`), not just the original 12. What each index means is data in `components/players/avatar-parts.ts`:
  - `a % 12` → the base look: hat (`a % 6`: cap, beanie, … 6 hats), skin tone (`a % 3`, index into `FILLS`), glasses + smile or mustache (`floor(a / 6) % 2`), tie on odd indexes. Shirt and photo variant as before.
  - `floor(a / 12)` → the variant in `VARIANTS`: 0 = the plain original; 1 = arched brows + freckles; 2 = thick brows + beard; 3 = angry brows + freckles.
- **Indexes 0–11 must never change their look** (saved in users' browsers). New looks only go at the END of `VARIANTS`; the order decides which index gets which look. Keep `avatarLook` and `Avatar.svelte` in step, and the extra features must stay off for photo avatars.
- `avatarLook(a)` accepts any number (negative, fractional, huge, NaN wraps into `0 … AVATAR_COUNT - 1`).
- **The avatar builder** (`components/sheets/AvatarSheet.svelte`, name `avatar`): tapping a player's avatar in `PlayersSheet` calls `openAvatarBuilder(i)`; the sheet has a large live preview, a row of **quick styles** (classic, man, woman, cool: `STYLES` in `avatar-parts.ts`, applied by `setAvatarStyle`; each sets several parts and keeps hat, skin, brows, freckles and the rest), a row of four tab chips (`.bldt` / `.bldtab`, plain `aria-pressed` buttons, no sliding pill) for the **pages**, and one chip row per part of the open page. Each chip is a small `Avatar` showing the current face with only that part changed. Pages and rows: **Față** (skin, glasses|mustache, glasses frames, mouth, brows), **Păr** (hat or no hat, hair style, hair colour, beard), **Haine** (clothes, tie), **Detalii** (lashes, lipstick, blush, freckles, earrings). A row with a `show` rule is hidden while it would change nothing: frames, mouth and lipstick need no mustache, the hair colour needs hair, the tie needs the shirt. Below the rows: a dice button, photo add / change / remove and \"Gata\" (back to the players sheet). The open page is local state of the sheet (it starts on the face page each time). Choices apply live to `state.players[i]` (`setAvatarPart`, `setAvatarStyle`, `randomizeAvatar` in `stores/players.svelte.ts`); there is no save step.
- **`Player.l` is saved data**: one bit-packed look code (28 bits, 0 .. `LOOK_MAX` = 268435455). The bit layout (`LOOK_BITS`) and `BROW_ORDER` in `avatar-parts.ts` must never change. **Only ever add bits on top, and make 0 mean the original look**: bits 0-11 are the first builder (hat, skin, glasses|mustache, tie, brows, freckles, beard; `BASIC_LOOK_MAX` = 4095), bits 12-27 added hair style (8), hair colour (3), lashes, lips, earrings, blush, clothes (4), glasses frames (4) and mouth (5). A new brow style goes at the END of `BROW_ORDER` (max 8); a new hair style, mouth or hat at the end of its table (hair 8 and mouth 8 fit the bits, hats 8 too; more needs a new bit field). `NO_HAT` (6) is a hat value no old code uses. `tests/unit/avatars.test.ts` pins the layout and proves that every code saved before (0-4095) still decodes to the same face with every extra off. 1680 looks exist without the extras (7 hats x 3 skins x glasses|mustache x tie x 5 brows x freckles x beard).
- The extras are drawn only for drawn faces: hair, lashes, lipstick, blush, earrings, frames, mouths are off for photos; hats and clothes are drawn on photos too. Glasses frames, mouth and lipstick are only drawn without a mustache (the mustache replaces them, as before). Hair is data (`HAIR`: `back` behind the head and ears, `front` over the head and under the hat, in the head's 48-unit space), so are `MOUTHS`, `LASHES`, `BLUSH`, `EARRINGS`; clothes and glasses frames are inline in `Avatar.svelte` like the hats. Hair colours are `HAIR_FILLS` (ink, the beard grey, white; always drawn with an ink edge).
- Codec (pure, in `avatar-parts.ts`): `lookToCode`, `codeToLook` (invalid input gives `DEFAULT_LOOK`, never throws), `isLookCode`, `indexToCode` (lossless for 0-47), `codeToIndex`, `closestIndex`, `playerCode` / `playerLook` (what a player is drawn with), `randomLook` (half feminine: long or tied hair, lashes, lips, earrings, a blouse, never a beard or mustache; half masculine), `randomFreeCode`, `applyStyle` / `hasStyle` (quick styles).
- `a` stays meaningful: when a built look equals a legacy face, `a` is set to that index; otherwise `a` keeps its old value (new players get `closestIndex`). A player without `l` looks exactly as before: no migration.
- Handing out faces: `addPlayer` gives a random look code nobody at the table has (`randomFreeCode`). Duplicates are allowed (the builder only shows a soft hint, `hasTwinLook`). `cycleAvatar`, `firstFreeAvatar` and `nextFreeAvatar` were removed.
- **Online avatars are the drawn ones only**: `l` (a look code, validated with `isLookCode`) travels in `create` / `join` / `rejoin` / `look` and in `PublicState.players`. A photo (`ph`) is never sent (too big, and private).
- Groups, the rematch card and `session.ts` copy players with `{ ...p }`, so `l` and `ph` travel with them.
- Drawing details: the beard is mid-grey (`BEARD_FILL`) with a thin ink edge, inside the head outline, with a second head outline drawn over it; freckles are one path of zero-length round-capped strokes (`FRECKLES`, `FRECKLE_STYLE`).
- The photo's circular clip `#phclip` is defined once, in the sprite in `src/app.html`; never define it again inside a component. There is no `av()` string helper.
- Tests: `tests/unit/avatars.test.ts` (originals pinned, codec and layout pinned, store wiring, SVG parts; `AVATAR_DUMP` also writes the builder combinations to `<dir>/builder/`), `tests/unit/avatar-sheet.test.ts` (the sheet mounted through `App`).
- CSS for the builder is in `styles/features.css` and `styles/themes.css` (`.bldp`, `.bldn`, `.bld`, `.chip.tile`, `.bldb`); it reuses `.chips` / `.chip`.
