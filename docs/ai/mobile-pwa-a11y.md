# Mobile, battery, offline, PWA, accessibility, assets

## Offline / PWA
- `static/manifest.json` + icons in `static/icons/`, and `src/service-worker.ts` (auto-registered by SvelteKit) precaches every build file, static file and the SPA shell under a cache named after the build version. It never calls `skipWaiting()` on its own (only on a `SKIP_WAITING` message from the page while the player is at rest).
- Anything new that must work offline has to be same-origin and served from `static/` or the build. Do not load assets from a CDN.
- Fonts are self-hosted **WOFF2** (`assets/fonts/`, declared in `styles/fonts.css`). No Google Fonts links; convert new fonts to WOFF2 (`fonttools` with `brotli`).
- Backgrounds (`assets/backgrounds/img-NN.webp`) are compressed WebP (long edge max 1280 px, quality 60–70, method 6) plus `img-NN-sm.webp` 480 px variants (only where smaller), picked in `Background.svelte` by `matchMedia("(max-width:820px)")` and lazy-loaded. A new background follows the same process.
- **Desktop skyline**: from 1000 px up, two blocks of buildings (left: radio mast, water tank, searchlight; right: a red "?" sign) stand beside the 480 px app column. They are generated inline SVG (`components/layout/skyline.ts`, no files to download), appended inside `.bgart` by `Background.svelte`, and shown by `.bgart .bgw.flank` in `styles/base.css` (hidden below 1000 px, so phones never lay them out). They reuse the existing animation classes (`.tw .bl .sm .sweep .mb`) and sit inside `.bgw`, so lite mode, reduced motion, the dark-theme filter and the paused-off-home rules cover them with no extra CSS; keep any new animated part on those classes and give every new `id` a unique name (the svgs share one document). `tests/unit/skyline.test.ts` guards this.

## Mobile and battery rules
1. **Screen Wake Lock** (`utils/wake-lock.svelte.ts`) holds the screen on only while a round screen (`MID_ROUND`) or the online round is showing.
2. **Audio**: always get the context through `getAudioContext()` (it resumes a `suspended` or iOS `interrupted` context); `initAudioLifecycle()` suspends it while the page is hidden.
3. **Storage**: `requestDurableStorage()` asks the browser not to evict saved data; saving stays in `persist.svelte.ts` (also on `pagehide` / `visibilitychange`).
4. **Service worker**: navigations are network-first but fall back to the cached shell after `NAV_TIMEOUT_MS` or on any failure / server error; navigation preload is on. `utils/sw-update.ts` checks for a new build when the app returns to the foreground and lets a waiting worker take over (then reloads once) **only** when `boot()`'s `canReload()` is true (setup screen, no sheet, not in an online room): never interrupt a round. Pinned by `tests/unit/service-worker.test.ts` and `sw-update.test.ts`.
5. `src/app.html` has a tiny inline script that applies the saved theme and accent before first paint (no white flash for dark themes); it must read the same key as `storage/keys.ts` (a test checks it).
6. **🐞 performance debugger** (`components/debug/`): developer tool, a lazy chunk loaded only with `?debug=1` (remembered; `?debug=0` turns it off); its CSS is a string in `debug/styles.ts`, not in `styles/`. `stats.ts` = pure maths and diagnosis rules (tested in `tests/unit/debug.test.ts`), `metrics.ts` = live monitor, `inspect.ts` = animation inspector and page audit, `features.ts` = switchable experiments, `scenarios.ts` = auto-profile, `debug.ts` = UI. Keep it free of `any` and `innerHTML`, and of app imports outside `debug.ts`. New experiments go in `FEATURES`; their ids are saved in localStorage, so never rename one.
7. The tap ripple is skipped in JS on touch devices (CSS hides it there anyway); do not build DOM for effects that CSS hides.
8. **Weak-device hint** (`components/settings/lite-hint.ts`, started by `boot()`): if lite mode is off, the player never touched that switch and we never asked, a 45 s `requestAnimationFrame` watch (`createFrameJudge` in `utils/frame-stats.ts`) can offer "Mod telefon slab" once per device (`LITE_HINT_KEY`), only at a calm moment. Do not weaken the "once" or "respect liteSet" rules. Touch devices already get lite mode on by default.
9. **Theme / accent changes must stay cheap**: the "?" wallpaper (`.bgq`) is colour-less masks painted with `--qink` / `--red`, so `applyTheme()` never builds or swaps an image (never bring back image URLs holding the accent colour). The sheet tile picks a pre-built accent tile through `html[data-acc]`: a new accent in `ACCS` needs its `html[data-acc="HEX"]{--qs-acc:...}` rule in `motion.css` (a test enforces it). The theme cross-fade is mouse-only and is ONE picture of the whole page (`pickTheme` uses `document.startViewTransition`; CSS `::view-transition-*` in `themes.css`); never go back to fading individual elements (gradients and shadows cannot fade, so it flashes).
10. **No `background-attachment: fixed`** anywhere (`tests/unit/wallpaper.test.ts`). The page gradient is the fixed GPU layer `html::before` (`performance.css`); the `html` background is a flat colour set in `card-designs.css`. The sheet dim on phones (`.scrim::before`) is a flat colour with no animation.
11. Prefer cheap paint: avoid new `filter` / `box-shadow` animations on screens that stay open for minutes.
12. **Installed-app extras** (see README "Installed app (PWA)"): the manifest has `display_override` (window-controls-overlay, then fullscreen, then standalone; the overlay rules and the `#tb` drag strip are at the end of `base.css` / in `app.html`), two `shortcuts` and a `share_target`; `theme_color` / the `theme-color` meta follow the theme (never a coloured bar: only `background_color` is red); `src/app.html` carries 18 flat-red `apple-touch-startup-image` links for `static/splash/*.png`; `boot()` calls `runShortcut()` (`utils/launch-intent.ts`, parser in `utils/shortcut.ts`), `initNetworkStatus()` and `clearBadge()`; `online/client.svelte.ts` calls `setBadge(1)` when a round or the results arrive while the page is hidden. Fullscreen mode must be treated like standalone wherever the app checks for an installed app (`(display-mode: standalone), (display-mode: fullscreen), (display-mode: window-controls-overlay)`). A new shortcut needs its `?shortcut=` value in `utils/shortcut.ts`, a branch in `runShortcut()` and passes `tests/unit/pwa.test.ts`.

## Accessibility
- Every `go()` moves focus (done by `App.svelte`) to the screen heading (`focusScreenHeading` in `stores/ui.svelte.ts`: first `h1`, else `role="heading" aria-level="1"`, else `h2`). A step inside a screen that swaps its content (the pass gate → card) must move focus itself.
- The talk timer is announced through the polite live region in `TimerRing` (text from `talkClock.say`, set only at whole minutes, 30 s, 10 s, time up and on pause / resume / +1 min).
- Motion: a global `prefers-reduced-motion` rule in `styles/base.css` covers CSS animation; SMIL in SVG is stripped by `utils/reduced-motion.ts`; code that uses `element.animate()`, `requestAnimationFrame` or smooth scrolling must check `prefersReducedMotion()`.


## Performance pass notes (unprofiled: no browser was available)
- `components/ui/icons.ts`: symbols are read from the sprite once and cached; in "Mod telefon slab" (`state.lite`, auto-on for touch devices) icons use their static resting drawing. Set `LITE_STILL_ICONS = false` to keep idle icon animations in lite mode.
- `utils/smil.ts` (`freezeSprite`): the icon sprite is never drawn, so its SMIL clock is paused in every mode.
- `animations/motion.ts`: forced reflow only when an animation must restart; sheen and sparks skipped on touch (CSS hides them there); sparks batched.
- `TimerRing.svelte` + `motion.css`: the per-second ping alternates `ping`/`ping2` (identical keyframes) instead of forcing a reflow.
- `storage/persist.svelte.ts`: identical snapshots are not rewritten; writes wait for idle (max 2 s). Page hide still flushes at once.
- `components/game/confetti.ts`: one batched insert and one cleanup timer.
- `performance.css`: `html.lite .bgart .ai{will-change:auto}` (no permanent GPU layers while lite stops their animation).
- Golden `setup.two-groups-no-current-lite.html` regenerated on purpose: the only change is 30 removed SMIL tags.

## Phone scrolling / menu lag pass (Oct 2026, from code reading, not yet profiled on a device)
- `performance.css` (last block): on touch / narrow screens with lite OFF, SVG-child animations in `.bgart` and the `.hero2` svg, the `.bgart::before/::after` drift and their `will-change` are off; only the `.ai` image drifts (compositor) keep running. Reason: SVG-child and gradient-layer animations repaint on the main thread every frame, also behind an open sheet (the `html.sheetopen` pause is desktop-only on purpose, it flashed on phones).
- `sheet-drag.ts`: the body-drag `touchmove` is passive (a non-passive one made Chrome wait for the main thread on every move, janky sheet scrolling). It relies on `.sheet{overscroll-behavior-y:contain}` and never calls `preventDefault`.
- `themes.css`: `--dim` is a registered non-inherited property (`@property`), and `.scrim::before` takes it with `inherit`, so a drag move restyles the scrim only, not the whole sheet subtree.
- Still open if lag remains: `{#key nav.n}` rebuilds the whole screen on every `go()`; the `--k` stagger loop in `App.svelte` and entrance animations run when lite is off; SMIL icons on the screen behind run idle until a sheet opens (`SheetLayer.svelte`). Bisect with `?debug=1` (`debug/features.ts`) before changing them.
