# Word tool

Generate new words ahead of time, read them, then add them to the game. Nothing reaches the game without you reading it.

1. **Choose how to ask the model**
   - **No key at all:** `pnpm words:generate --cat "Animale" --prompt-only` writes a prompt file to `scripts/words/pending/_prompts/`.
     Paste it into any AI chat (Claude, ChatGPT, Gemini), save the answer to a file, then
     `pnpm words:generate --cat "Animale" --reply answer.txt` turns it into the review file (step 2 below).
   - **Free key:** a Google Gemini key from aistudio.google.com: `$env:GEMINI_API_KEY="..."` (PowerShell).
   - **Anthropic key** from console.anthropic.com: `$env:ANTHROPIC_API_KEY="sk-ant-..."`.
2. **Generate**: `pnpm words:generate --cat "Animale" --count 30` (or `--all --count 20`).
   It asks the model, removes duplicates (against every list), words with odd characters and blocked words, and writes
   `scripts/words/pending/ro/animale.txt`.
3. **Review**: open that file, delete the lines you do not want or fix a spelling, save.
4. **Apply**: `pnpm words:apply` adds the words to the list file and updates `counts.ts`. Add `--dry` to preview.
5. `pnpm test`, then commit. `pnpm words:check` checks every list against the test rules at any time.

## Other languages (local words, not translations)
Each language is generated for its own audience: the prompt tells the model who the players are (for example English speakers
in the USA and UK) and not to translate the Romanian list, which is only a style example. So the English "Personalități"
gets celebrities English speakers know, not Romanian ones. Read the review file with that in mind: you decide what stays.
`--lang en` generates English words into `scripts/words/pending/en/`, and `apply` writes them to
`src/lib/data/words/en/<category>.ts`. **The app does not load other languages yet** (every screen text and the category names
are Romanian), so those files wait until the game has a language setting. The Romanian list is used as the style example.

## Notes
- The model is `claude-sonnet-5-5`; change it with the `WORDS_MODEL` environment variable.
- Twin-word pairs (`words/pairs/`) are not generated by this tool yet.

## Wikidata: real fame data, no key, no cost
For people and works, `pnpm words:wikidata` lists who is actually known to an audience, from Wikipedia / Wikidata data instead of a model's guess:

    pnpm words:wikidata --cat "Personalități" --lang ro                  famous living Romanians with a Romanian Wikipedia article
    pnpm words:wikidata --cat "Personalități" --lang en                  worldwide stars with an English article
    pnpm words:wikidata --cat "Personalități" --lang en --country US,GB  only Americans and Britons
    pnpm words:wikidata --cat "Personalități" --lang en --views          rank by Wikipedia page views of the last 12 months

Categories with a preset: Personalități, Politicieni, Muzică românească, Filme și seriale românești, Filme și desene (edit `PRESETS` in
`wikidata.mjs` to change occupations or add categories). Options: `--count` (default 40), `--min-links` (how many language editions an
article needs, raise it for a stricter "famous" bar), `--country`, `--views`, `--show-query` (prints the query).
It writes the same review file as `generate`, with a note after each name ("# 85 languages, 1,200,000 views/year") that you can read and that
is ignored on apply. Duplicates, blocked words and names already in any list are removed as before. If Wikidata times out, raise `--min-links`.

## Exactly 100 words per category
- `pnpm words:status --to 100` lists every category with how many words it has and how many are missing.
- `pnpm words:generate --cat "Animale" --to 100` (or `--all --to 100`) asks for exactly what is missing, plus spares for the filter.
  `pnpm words:wikidata --cat "Personalități" --to 100` does the same from Wikidata.
- `pnpm words:apply --to 100` never lets a list go above 100: extra lines in a review file are left out (and listed).
- If a run is SHORT (the filter removed too many), run the same command again: it asks only for what is still missing.
- Categories that already have 100 are skipped. Run `pnpm words:status --to 100` at the end: every line should say `ok`.

## Same concepts or local words? (per category)
- **Universal categories** (Animale, Mâncare, Obiecte, Sport, Transport, Haine, Natură, Meserii, Casă, Corpul uman...): in another language the tool
  **translates the Romanian list one to one**, so everybody plays with the same animals, foods and objects. Fill and review the Romanian list first
  (`--to 100`), then run `pnpm words:generate --cat "Animale" --lang en --to 100`. Each review line shows its source: `tiger  # from: tigru`.
  If two Romanian words share one English word, the second is dropped and the run says SHORT; the list then needs a local extra word.
- **Local categories** (Personalități, Politicieni, Muzică românească, Filme românești, Mâncare tradițională, Locuri din România, Proverbe, București, Anii '90, Eurovision,
  Crăciun, Sărbători, Tradiții, Paște și Halloween, Basme, Filme și desene, Petrecere): another language gets its **own words for its audience**
  (`generate` or `wikidata`). The list of local categories is `LOCAL_CATEGORIES` in `lib.mjs`.
- Force one way with `--mode translate` or `--mode local`.

## From word files to a playable language
`pnpm words:apply` writes another language into `src/lib/data/words/<lang>/<file>.ts`. The app finds these folders by itself (no code change).
A language becomes selectable in Settings ("Limbă / Language") as soon as it has at least 8 categories. A category without a file in that language
is simply not offered there, and category names are translated in `src/lib/data/category-names.ts`. Twin words ("Cuvinte gemene") still need
Romanian pairs, so they are off in other languages. The screens' own texts move to `src/lib/i18n/` step by step: `pnpm i18n:scan` lists what is still hard-coded.
